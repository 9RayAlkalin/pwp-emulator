# 谱面导入与适配

谱面可与音乐、可选曲绘一起选择或拖入，也可打包为 PEZ / ZIP。格式依据内容或元数据的 `format` 字段判断，不依赖谱面扩展名。支持 Phigros v1/v3、PEC、RPE；PBC 尚不支持。

## 元数据与资源

同一字段按 `info.yml / info.yaml` → `info.txt` → `info.csv` → `info.json` → RPE `META` 的顺序取首个非空值。未填写的字段继续向后查找。文件路径可相对于元数据文件或谱面文件，支持子目录、反斜杠及大小写差异。一次导入多个压缩包时，每个包独立匹配资源。

`info.txt` 示例：

```text
#
Name: 自制曲
Song: music.ogg
Picture: cover.png
Chart: chart.pec
Level: IN Lv.14
Composer: 曲师
Charter: 谱师
Illustrator: 画师
```

用独立的 `#` 行分隔多条记录；每条记录的 `Chart` 指定对应谱面。`Music` / `Image` 是 `Song` / `Picture` 的别名，兼容 CSV 的同名字段。曲名可包含冒号，路径可用引号包裹。

`info.yml` 示例：

```yaml
name: 自制曲
chart: chart.json
format: Rpe
music: music.ogg
illustration: cover.png
level: IN Lv.14
offset: 0.0
```

YAML 读取 ChartInfo 的顶层标量字段，支持单引号、双引号、注释、简单多行标量；不解析锚点、别名或自定义标签。`offset` 以秒为单位，附加到谱面自身偏移。此偏移为正时，谱面相对音乐更晚开始。

显式资源路径不存在会报错。没有指定音乐时，只在同目录或当前包内只有一首音乐的情况下自动匹配，避免多音乐时误选。没有指定曲绘且无法唯一匹配时，可使用默认曲绘。

无法解压的 PEZ/ZIP 会报告包文件名，提示压缩包可能损坏或不完整、需要重新下载或重新导出；不会把仅恢复了部分资源的包当成完整谱面导入。

## 适配范围

PEC 支持 `bp`、`n1`–`n4`、`#`、`&`、`cv/cp/cd/ca/cm/cr/cf`。偏移遵循本地 phira-docs 的 `(首行毫秒值 - 175) / 1000` 约定。坐标按 2048×1400 换算，流速转换为当前模拟器单位时除以 7。

RPE 支持三元分数拍、BPMList、`bpmfactor`、四类音符、正反面、假音符、宽度、透明度、可见时间、Y 偏移、判定宽度、多层事件相加、XY 分离、嵌套父线、`rotateWithFather`、遮罩、判定线 zOrder、颜色/文字/缩放。坐标按 1350×900 换算，流速除以 4.5。`size` 只改变音符宽度。父线旋转作用于子线位置；子线角度仅在明确设置 `rotateWithFather: true` 时继承。

RPE 默认 `line.png` 按 4000×5 个 RPE 坐标像素换算，并应用 `scaleX/scaleY`；原生 Phigros 继续使用自身 Unity Sprite 的世界空间尺寸，不共用线长/线宽常量。自定义贴图、文字和 PEC 的现有尺寸路径不受这项修正影响。这里没有新增 `info.yml lineLength` 设置支持。

普通线、纹理和文字属于互斥的绘制类型：一旦存在文字事件，事件前或空文字时也不回退绘制线/纹理。判定线层按 zOrder 从小到大绘制，同值保持谱面顺序；负 zOrder 的 GIF 位于普通文字下面，但仍可透过文字轮廓以外的空白看到。

默认谱面文字使用已加载的 `PhiHUD`（Saira Regular 与思源黑体混合字体）；文字事件明确指定包内 TTF/OTF/WOFF 字体时单独加载，不覆盖默认字体，换谱时释放。`%P%123` 与兼容的 `123%P%` 数值事件会按原缓动计算，保留弹性、贝塞尔等过冲；新开始的文字事件覆盖仍在持续的旧事件，倒退可重新计算。

`alphaControl`、`sizeControl`、`posControl`、`yControl`、`skewControl` 接入音符实际绘制。控制器采样坐标为未乘音符速度的积分距离加 `yOffset`，再计算纵向倍率、横向倍率、尺寸、透明度和斜切；`note.speed` 只在投影距离上乘一次。除 AlphaControl 外其余控制器不作用于 Hold。`inclineEvents` 按音符横向位置和距离产生线局部坐标的横向收束，正反面方向相反，不是把整条线当普通平面旋转。判定与反馈使用判定位置处相同的偏移/倾斜/XY投影，避免只变图形而判定原点不变。

音符 `tint` / 旧名 `color` 与 `tintHitEffects` 支持 RGB 染色，明确指定的特效色同时用于 Perfect/Good。`attachUI` 的颜色事件作用于对应文字、暂停和进度图标。静态 sprite 染色有容量限制并复用，不逐帧复制全部原图。

包内 `hitsound` 资源用于实时自动/手动打击，假音符不会触发。导出音轨仍沿用音乐/结算 BGM 路径，不混入打击音。负流速 Hold 保留头尾的有向积分距离，不再将负长度截为零；非 Hold 的 isCover 遮罩会实际裁掉线背面的图像。RPE 的真假 Hold 在起拍后都贴线回收头部，尾部继续按有向流速积分变化，适用于停速、反向或多层变速，假 Hold 仍不判定、不计分、不发声和特效。该视觉约定已用用户提供的 RPEN 参考视频核对，替换了之前按文档保留假 Hold 未打击头部的实现；PEC 和原生 Phigros 的假 Hold 路径不因此改变。

自定义 `Texture` 从谱面包中匹配 PNG / JPEG / WebP / BMP / GIF，保留透明度、旋转、缩放、颜色事件和 `anchor`。纹理每个像素在两个方向均按有效谱面视口宽度 / 1350 换算，保持图片自身比例；改变窗口宽高比不会分别拉伸图片的 X/Y 像素。自定义纹理不采用 AP/FC 判定线颜色。缺少明确指定的图片会报错，不替换为整屏判定线；纹理图片也不会被自动匹配为曲绘。文字事件优先于纹理，并应用文字锚点。

GIF 使用浏览器 `ImageDecoder` 预解码为完整帧，按谱面时间和帧时长循环；`extended.gifEvents` 在事件区间内控制帧进度，区间之外恢复自动循环。暂停、倍速、倒退和导出均使用谱面时间选帧，换谱时释放解码资源。需要支持 GIF ImageDecoder 的新版 Edge / Chrome；不支持时会明确报错。

判定线贴图按解码帧、显示精度与颜色共享缓存，透明、零缩放和完全离开视口的贴图在染色前跳过。大图按实际画布像素选择向上取整的缓存精度级别，避免窗口内几十张4K图片反复挤出缓存；放大、提高DPR或导出分辨率时会选择更高精度，原图保留不变。灰度明暗使用 Canvas brightness 绘制，避免为每一种灰度复制整张图片；不支持 filter 时使用染色缓存。缓存最多保留 128 份、约128 MiB RGBA 像素，支持时保存为不可变 ImageBitmap，换谱时释放。同一资源的路径别名复用解码结果，不修改颜色事件或减少 GIF 帧；显示级别与不同合成路径可能带来细小的采样/舍入差异，首次生成较大缓存仍有开销。

`attachUI` 支持 `pause`、`combonumber`、`combo`、`score`、`bar`、`name`、`level`。绑定线控制对应 HUD 元素相对于默认位置的位移、旋转、XY 缩放和透明度；绑定线自身不再绘制，音符仍使用该线坐标。旋转/缩放锚点分别为暂停左上角、分数右上角、曲名左下角、难度右下角、Combo 两项中心、进度条左侧中心；文字的绘制中心与角落锚点分别计算，避免翻转后被额外推出屏幕。Combo 仍在连击至少为 3 时显示；同一元素重复绑定时取最后一条线。暂停按钮的点击区域同步应用逆变换，透明或零缩放时不接受点击。

两侧 cover 绘制在全部 HUD 之上，包含进度条、暂停、文字和经 attachUI 变换后的图形；动画仍可越过边界，越出的部分由 cover 盖住，不改位置、不缩小、不强制夹回。被 cover 盖住的暂停部分不响应点击，露出的部分保留命中。

PEC/RPE 共用有效谱面视口：默认宽高比 16:9，宽屏居中限制谱面宽度，较窄窗口使用全幅高度和宽度。`info.yml` 的正数 `aspectRatio` 可指定谱面宽高比。设置中的“谱面宽高比（宽 ÷ 高）”可覆盖它，`0` 跟随谱面；例如 `1.5` 为 3:2、`1.3333333333333333` 为 4:3，支持自定义到 4，立即应用并在刷新后保留，仅对 PEC/RPE 生效。

判定线平移分别映射视口宽、高；父子线旋转在当前视口的像素空间计算，暂停时改变窗口比例也会刷新状态。纹理、音符图片和反馈尺寸使用该视口尺度。音符的滚动距离、Hold 长度及 `yOffset` 使用完整画布高度，不再乘宽高比缩放；反馈的偏移使用相同高度单位。HUD 大小按画布高度定标，不随谱面变窄而缩小；暂停、分数、曲名、难度和进度条的左右锚点位于 cover 内侧，Combo 保持居中。只有明确设置了 `attachUI` 的元素再应用对应线的变换，暂停点击区域随布局与绑定一起更新。

内部适配时间统一为秒；以 `bpm = 60/32` 接入现有的 32 分拍时间轴。事件按 BPM 边界拆分且保留原曲线进度，跳转不会依赖之前播放状态。支持 1–29 号缓动、缓动裁剪和普通事件贝塞尔曲线。线性速度变化精确积分；非线性速度以 240 Hz 梯形近似积分（单段上限 65536 份）。PEC/RPE Hold 的头尾位置随积分流速变化，并在真实尾时间移除图形，避免尾图到线后额外停留 250 ms。Hold 反馈间隔使用起始时 BPM。

RPE 缓动裁剪的两个端点分别位于 0–1 内，可按反向区间取值，例如 `easingLeft: 1`、`easingRight: 0.5`；按原端点方向重新归一化，不交换端点或退回整条曲线。`visibleTime` 保留有符号秒数，负值可用于隐藏判定前的音符，不会因此删除音符、物量或判定；不将其强制改为 0 或正值。

RPE `META.offset` 按毫秒转换为 `META.offset / 1000`，正数表示谱面相对音乐延后。运行时使用 `谱面秒 = 音乐秒 - META.offset / 1000 - info.offset`；例如 `META.offset = 1315`、外部偏移为 0 时，音乐第 1.315 秒对应谱面第 0 秒。此方向已用焦糖星参考视频的音轨与 Combo 时序验证。PEC 首行 `275` 则对应谱面延后 0.1 秒。

RPE 的首个非流速标量事件在第 0 拍或更早开始时，其开始值也用于更早的起播预览，保持谱面设置的初始位置、角度、透明度、缩放和颜色；不会将屏外停放的线临时移回中心。第 0 拍之后才开始的事件保留原默认值，流速仍从显式事件积分，负时间事件继续正常求值。

假音符保留视觉，排除手动判定、自动计分、打击音和打击特效。RPE 中 fake note 与真音符共同参与同刻多押高亮，fake/fake 同刻也会高亮；按 RPEN 的微秒时间桶合并起拍，不按 Hold 持续区间算多押。`highlight` 的 0/1/2 分别关闭、自动、强制高亮，关闭的音符不贡献同刻高亮计数。PEC 和原生 Phigros 保留既有规则。透明度为负的线会隐藏其音符；RPE `isCover: 0` 可显示线背面音符。

RPE Hold 的头/尾端帽分别以真实积分头尾为中心，身体只填充两者之间的区间；反向时身体及端帽同步纵向镜像。短身体不会把尾帽叠到未打击头部里，零速的未打击头仍可见；起拍后零跨度不留孤立尾帽。此端帽修正不改变 PEC 或原生 Phigros 的 Hold 布局。

以下内容仍会显示兼容提示：未知 UI 绑定名称、画笔以及 RPE 162–169 的旧非线性流速规则；无法匹配非文件字体名时使用默认字体并提示。倾斜/距离控制器已验证特定参考片段，但不声称原编辑器全行为、全版本或逐像素等价。视频、extra 着色器和解锁视频尚未接入。
